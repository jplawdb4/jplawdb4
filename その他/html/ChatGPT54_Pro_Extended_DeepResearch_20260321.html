2.3 GPT-5.4の位置づけ

GPT-5.4は「初の真のメインライン推論モデル」と位置づけられている。それまで推論能力はo1/o3シリーズに分離されていたが、GPT-5.4ではメインラインモデルに推論能力が完全統合された。さらにGPT-5.3-Codexの業界最高水準のコーディング能力も取り込み、推論・コーディング・エージェント動作を単一モデルで実現する。

GPT-5.4の歴史的意義 GPT-5.4は、それまで別系統だった「高速汎用モデル」「推論モデル（o-series）」「コーディングモデル（Codex）」を初めて単一モデルに統合した。これにより、ユーザーはタスクに応じて異なるモデルを切り替える必要がなくなり、推論努力レベルのパラメータ1つで動作特性を制御できるようになった。

3.2 コンテキストウィンドウとトークン制限

GPT-5.4は1,050,000トークンのコンテキストウィンドウを持つ。これはシェイクスピア全作品の約40%を一度に処理できる量に相当し、コードベース全体、長大な文書コレクション、エージェントの長期的な実行軌跡を単一リクエストで分析可能にする。

長文コンテキストの料金階段
  • 272Kトークン以下: 標準料金（$2.50/1M入力）
  • 272Kトークン超過: 入力料金が2倍（$5.00/1M入力）
この料金階段はバッチ処理やデータレジデンシーの料金とも重複適用される。長文コンテキストを活用する場合のコスト設計には注意が必要。

実効的な制限事項

  • 最大出力: 128,000トークン（全バリアント共通）
  • レート制限: 標準コンテキスト（≤272K）と長文コンテキストで異なる制限が適用
  • temperature/top_p: reasoning.effortがnoneの場合のみ使用可能。他の推論レベルでは指定するとエラー

3.3 推論努力レベル（Reasoning Effort）

GPT-5.4の最も重要な制御パラメータがreasoning.effortである。このパラメータは、モデルが最終回答の前に生成する内部推論トークンの量を制御する。

レベルAPI値特徴推奨用途レイテンシ
なし none 内部推論なし。GPT-5.4のデフォルト 高速チャット、分類、テンプレート生成 最速
最小 minimal ごく軽い推論 簡単な質問応答、要約 非常に速い
低 low 基本的な推論 レイテンシ敏感なタスク 速い
中 medium バランス型推論 o3からの移行時の起点 中程度
高 high 拡張推論 複雑な問題解決、コード生成 遅い
最高 xhigh 最大深度の推論 長時間エージェント作業、博士レベルの問題 最遅（8分超あり）
重要: デフォルトはnone GPT-5.4のデフォルトはnone（推論なし）であり、旧GPT-5モデルのmediumデフォルトから変更されている。推論が必要なタスクでは、明示的にeffortレベルを設定すること。設定を怠ると推論なしの低品質な回答が返される可能性がある。

3.4 冗長性制御（Verbosity）

推論努力とは独立した出力長の制御パラメータ。

3.6 コンピュータ操作（Computer Use）

GPT-5.4は汎用モデルとして初めて、ネイティブのコンピュータ操作能力を備えている。スクリーンショットの解析、マウス・キーボードの操作指示、Playwrightを用いたブラウザ自動化コードの生成が可能。

動作メカニズム

  • スクリーンショットからUI要素を認識
  • マウスクリック/キーボード入力のアクションを構造化データで返却
  • 実行ハーネスがアクションを実行し、新しいスクリーンショットを再送
  • Build → Run → Verify → Fixのループ

ベンチマーク成績

  • OSWorld-Verified: 75.0%（人間: 72.4%を超過）
  • Online-Mind2Web: 92.8%（スクリーンショットのみ）
  • GPT-5.2の47.3%から大幅改善
安全上の注意 コンピュータ操作はサンドボックス環境での実行が必須。人間の監視（human oversight）を伴う設計が推奨されている。不可逆な操作（ファイル削除、送信等）の前には必ず確認ステップを設けること。

3.7 ツール検索（Tool Search）

GPT-5.4の新機能であるツール検索は、従来の「全ツール定義をプロンプトに載せる」方式を根本的に変える。

従来の問題

多数のツール（MCPサーバー等）を接続すると、全ツールのスキーマ定義がプロンプトに含まれ、トークンコスト・レイテンシ・コンテキスト汚染の三重課題を生んでいた。

ツール検索の解決策

  • 軽量なツールリスト（名前+説明文のみ）をモデルに提供
  • モデルが必要に応じてツール定義を動的に検索
  • 関連するツールスキーマのみをロード

実測効果

36のMCPサーバーを接続した250タスクのMCP Atlasベンチマークで、トークン使用量を47%削減しつつ、精度は同等を維持。

Tool Searchの対応範囲 Tool Searchはgpt-5.4以降のモデルでのみサポート。ホスト型（サーバーサイド）とクライアント実行型の両方に対応。大規模ツールエコシステムでのコスト/レイテンシ最適化に特に有効。

4.1 思考レベル: Light / Standard / Extended / Heavy

ChatGPT上でGPT-5.4 Thinkingを使用する際、ユーザーは4段階の思考レベルを選択できる。各レベルは内部推論に割り当てる計算資源と時間の量を決定する。

レベル 内部値 利用可能プラン 特徴 典型的な応答時間
Light Pro限定 — Pro 最速。日常的な質問応答、簡易な要約に最適 1秒以下
Standard — Plus / Team / Pro 新デフォルト。速度と知能のバランス 数秒
Extended Level 64 Plus / Business / Pro 高度な推論。複雑なロジック、詳細なリサーチ 10〜30秒
Heavy Pro限定 Level 200 Pro 最大深度。博士レベルの問題、複雑な多段階ワークフロー 5〜15分

4.2 プリアンブルとステアラビリティ

GPT-5.4 Thinkingの最大の革新は「ステアラビリティ」（操縦可能性）である。

プリアンブル（前文）の仕組み

複雑なクエリに対して、GPT-5.4は最終回答の前に「プリアンブル」を生成する。これはモデルの計画を可視化したもので、どのようなアプローチで問題に取り組むかをユーザーに示す。

ユーザー質問
→
Chain-of-Thought（非表示）
→
プリアンブル表示
→
ユーザー介入可能
→
最終回答

中間介入（Mid-Response Adjustment）

従来の推論モデルでは、回答の方向修正には最初からやり直す必要があった。GPT-5.4では、モデルが思考中・回答生成中であってもユーザーが介入して方向を修正できる。

ステアラビリティの活用例
Step 1: 「移転価格税制の各国比較分析をして」と質問
Step 2: モデルがプリアンブルで「5カ国を比較する予定」と表示
Step 3: ユーザーが「ASEANに絞って、特にインドネシアとタイを重点的に」と介入
Step 4: モデルが方向修正し、ASEAN焦点の分析を生成
→ 複数ターンのやり取り不要で、1回の対話で精度の高い結果を取得

  • Chain-of-Thought透明性: GPT-5.4は内部推論を隠蔽・難読化する能力が極めて低く、安全性システムによるモニタリングが容易

  • Computer Use安全フレーム: 不可逆操作の前にPre-flight確認を推奨。サンドボックス環境での実行が必須
  • 引用の正確性: 33%改善だがゼロではない。重要な事実は必ず検証

13.3 既知の問題

  • 長文回答での指示ドリフト（重要指示の再提示で軽減）
  • 会話中の指示変更の誤処理（<task_update>ブロックで軽減）

第15章 結論と推奨事項

15.1 GPT-5.4の本質的な価値

GPT-5.4は個々のベンチマークでの微差よりも、以下の統合的価値で評価されるべきモデルである。

  1. 統合: 推論・コーディング・コンピュータ操作・エージェントを単一モデルに統合し、モデル切替の複雑性を排除
  2. 制御性: 6段階の推論努力レベル+3段階の冗長性制御+ステアラブル思考で、タスクに応じた最適な動作特性を設定可能
  3. 効率性: ツール検索（47%トークン削減）、Responses API（40-80%キャッシュ改善）、miniの本体並み性能による大幅なコスト最適化
  4. プロフェッショナル性能: 44職種で83%の対専門家勝率は、実務活用の説得力ある根拠

15.2 推奨アクション

個人ユーザー向け

  • Plus($20/月)で十分か評価。Standard/Extendedで大半のタスクをカバー
  • Deep Researchヘビーユーザーや最高性能が必要ならPro($200/月)
  • 推論レベルを意識的に選択（デフォルトnoneに注意）
  • 出力形式を明示的に指定するプロンプト設計を習慣化

開発者向け

  • Responses APIへの移行を開始（3%性能+40-80%キャッシュ改善）
  • ツール検索の導入でコスト最適化
  • nano→mini→5.4の階層的ルーティング設計
  • One-Change-at-a-Timeの移行規律を遵守

組織向け

  • Business($25/user)で全員にGPT-5.4 Thinkingを提供
  • パワーユーザーにはProアドオンを検討
  • Projects機能でナレッジ共有基盤を構築
  • Deep Researchで定型リサーチの自動化

15.3 プロンプト設計の核心原則（まとめ）

GPT-5.4プロンプト設計 10箇条
  1. タスク形状に応じたreasoning.effortの明示的設定（デフォルトnoneに依存しない）
  2. 出力契約の具体的記述（形式・構成・長さ・引用形式を全て指定）
  3. 成功基準の明示（「完了」の定義を曖昧にしない）
  4. 検証ループの組み込み（最終化前チェックを必須化）
  5. ツール永続性ルールの追加（モデルに中止判断を委ねない）
  6. 引用ロック（ソース境界を明示し捏造を防止）
  7. 依存関係チェック（前提条件の確認を行動前に要求）
  8. 空結果フォールバック（最低2つの代替戦略を試行）
  9. 長時間セッションのphase管理（プリアンブルの誤解釈を防止）
  10. effortを上げる前にプロンプトを改善（推論コストは最後の手段）
