Ⅲ P0 — 即時実装（半日〜1日・全レンズ生存）

1. runner一本化（最重要）

  • 単一Python runnerが spawn（Popen・pid/pgid/start_ts記録）→watch→harvest→journal を一体で持つ。coordctlとの二重帳簿はしない。正典はjournal.d/<lane>.jsonlのみ、lanes.tsvは入力（手書き列はid/spec/effort/type/depsだけ）
  • 完了判定: final末尾行 LANE=<id> DONE-<nonce> ＋ exit 0 ＋ プロセス消滅後3サンプル安定。DONEが見えてもプロセス生存中は収穫禁止。nonceは完了マーカーであって信頼証明ではない（検収はrunner外側）
  • 収穫: 第一候補 --output-last-message＋--experimental-json（usageトークン構造化・スモーク実証済み）、旧ログは「最後のtokens used行の次行からEOF」フォールバック
  • 再投: attempt<2 かつ 起動失敗・nonce不一致・プロセス異常のみ。schema/内容の失敗は人間ゲート。kill はpgid+start_ts+cmd_hash一致時のみ（PID単独kill禁止）
  • バースト: 39B=BOOT_STUCK_WAIT（5分保留）・fatal markerのみ即DEAD・初回4体→6体刻みjitter

2. 文脈衛生（縮退版）

  • P0はclean cwd＋sandbox明示（read-only既定）＋-c features.memories=falseのみ（すべてスモーク実証済み）。現行configのdanger-full-accessをレーンに継承しない
  • worker prompt固定文「codexコマンド起動禁止」（教訓12）。PATH shim等の多重ガードは作らない

3. 品質機構

  • L0.5執筆前レッドチーム v2（4体Fable独立合議・20260705改訂）:
    • 発散遮蔽＋対抗骨子: RT投入前に対抗骨子2〜3案を生成し批判から遮蔽。RTは「選ばれた骨子の追認」ではなく複数の生きた選択肢からの選別として機能させる。RT前候補は定期的にユーザーへ棚卸し提示（早期淘汰された分岐を人間が見られる構造）
    • 評決の機械分離: 骨子段階で拘束力を持つのは「反証」（事実誤り・論理断絶・自己矛盾）のみ。「脱リスク」（言い過ぎ・露出・断定の強さ）は別枠に隔離し骨子に触れさせない——攻撃者には「最も突きやすい面＝露出」へ向かう勾配があり、混在させると全命題が守りやすい平均へ回帰するため。主宰の裁量による防波堤（手動棄却）に頼らずスキーマで分離する
    • 遮断の非対称基準: ブロックできるのは実証可能な構造的虚偽のみ。野心・リスク・守りにくさはブロック理由にしない。高分散の主柱を最低一本、反証以外では抜けない保護指定にできる
    • 再誘導の義務: 各攻撃には最強の修復案を必ず付す。「支えが未構築なだけ」の大胆な骨子への攻撃は、削除でなく「本文が生産すべき証拠の仕様書」へ変換する
    • 裁定の説明責任: 主宰の却下判断は理由を言語化してjournalに残す（命題の所有者が被告と裁判官を兼ねる利益相反への担保）
    • 指標の差し替え: 「書き直しゼロ」は成功指標にしない（後期の急旋回＝跳躍を罰する）。「救った跳躍／殺した跳躍」をjournalに記録。時々RT順序を逆転する対照試行（構造/較正の非重複が順序効果でないことの検証）
    • 帰納型執筆への適応: 観察から帰納する型の執筆では「骨子確定」は離散状態ではない——骨子RTは法廷でなく探針として扱い、執筆中に構造が動いたら短い再RTを許す
    • 発散段階: 拘束的RTは禁止のまま。ただし採否権のない刺激としての批評は許容（「批判は発想を殺す」自体が無検証の通俗観であるため）。blind検証にはRTログを渡さない（従前どおり）
  • 否定制約プリセット: constraint=legal_holding_v1（判示欄のみ・主張/判断の峻別・source_role列必須）等を名前で参照。全文貼付しない。本日の原告主張混入2件が直接根拠
  • 5行INTENT＋人間ゲート3つをGOAL契約冒頭の標準節に

4. 素材契約v2（縮退版）

  • 正典はclaims.tsv一本（状態はunverified/verified/rejected/holdの4値）。新規ラウンド分から適用、過去198候補のバックフィルはしない
  • verify_quotes.py（取得済みPDF/HTML内の逐語一括grep照合）を機械検証の先行段に。AI再検証は高リスク候補だけ小窓で
  • verify-or-dropは削除既定を維持（「反証条件つき降格」への緩和は却下——捏造リスク領域では未照合＝不使用。例外は照合期限＋期限切れ自動削除つきのみ）
  • fetchは主宰側バッチ限定・allowlist・サイズ上限（SSRF/悪性PDF対策）
