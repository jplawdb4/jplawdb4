Cogneeとは何か

Cogneeは、AIエージェントのための知識エンジン（メモリ基盤）である。ドキュメント、PDF、音声、画像など38以上のフォーマットからデータを取り込み、ベクトル検索とグラフデータベースを組み合わせた「グラフ-ベクトルハイブリッド」構造として知識を蓄積する。

核心的な特徴は「6行のコードでAIエージェントにメモリを付与できる」という簡潔さと、内部で実行される高度なパイプラインの両立にある。

2層メモリアーキテクチャ

セッションメモリ（短期記憶）

Redis上のワーキングコンテキスト。関連する埋め込みとグラフフラグメントをランタイムに読み込み、高速な推論を支援。session_idによる会話履歴追跡で、複数ターンにまたがる代名詞解決も可能。

永続メモリ（長期記憶）

ユーザーデータ、インタラクション痕跡、外部ドキュメント、導出関係をグラフ内で相互接続しつつ、ベクトルリンクも維持。静的ストレージではなく、フィードバックとインタラクションの痕跡に基づいて適応する進化的構造。

3. SKILL.md の問題 -- 静的スキルの限界

SKILL.mdの標準仕様

SKILL.mdは2025年10月にAnthropicが公開したオープン仕様で、エージェントスキルを自己完結的なディレクトリとして定義する。YAMLフロントマター（名前、説明、バージョン）とMarkdown本文（具体的な指示）の2部構成で、モジュラーかつ再利用可能なAIエージェント機能を標準化した。

根本的な問題点

問題詳細
静的性SKILL.mdは「書いたらそのまま」のテキストファイル。環境変化やタスクの進化に対して自動的に適応しない
スキル劣化ドメインの変化、ツールのAPI更新、ユーザー要件の変遷により、時間とともにスキルの有効性が低下する
フィードバック欠如実行結果（成功/失敗）がスキル定義にフィードバックされるメカニズムがない
ルーティング不在複数スキルがある場合、どのスキルが最適かを判断する仕組みがない。LLMの推測に依存
コンテキスト劣化Lost-in-Middle現象（中央の情報が注意を受けにくい）、コンテキスト汚染（エラーの複合）、コンテキスト混乱
メンテナンスコスト人間が手動で更新する必要があり、スケールしない
Vasilijevの問題定義: スキルは「ドキュメント」であるべきではなく、「学習可能な知識構造」であるべきだ。

4. 自己改善ループの技術解説

Cogneeスキル自己改善サイクル

→
Route
→
Execute
→
Observe
→
Promote
→
Route Better

次回のルーティングが前回の学習を反映 → 継続的改善

Step 1: Ingest（取り込み）

SKILL.mdファイルを解析し、フロントマター・指示文・付属リソースを抽出する。各スキルに安定したID、メタデータ、コンテンツハッシュを付与し、変更追跡を可能にする。

  • Markdownのフレンドリーなフォーマットから機械利用可能なフォーマットへ変換
  • upsert()で未変更スキルの再処理をスキップ
  • cogneeのadd()操作に対応

Step 2: Cognify（構造化エンリッチメント）

LLMによる構造化抽出を用いて、各スキルを以下の要素で強化する:

  • 整理された説明文 -- スキルの目的を簡潔に要約
  • 指示サマリー -- 実行手順の凝縮版
  • トリガーフレーズとタグ -- どのような要求でこのスキルが呼び出されるべきか
  • 複雑度レベル -- タスクの難易度分類
  • タスクパターン -- そのスキルが解決する候補タスク群

ここで決定的なのは、タスクパターンが独立したグラフノードとして具現化される点である。スキルとタスクパターンの間に「solves」関係エッジが張られ、「スキルについてのドキュメント」から「スキル・意図・関係の知識グラフ」へと構造が転換される。

Step 3: Route（ルーティング）

検索層は3つの操作を実行する:

  1. 意味検索 -- スキルサマリーに対するベクトル類似度検索
  2. パターン検索 -- タスクパターン記述に対するベクトル類似度検索
  3. 履歴検索 -- 過去の実行から学習した「preferred edge」のグラフ探索

ランキングは意味的類似度と過去の成功率のブレンドで決定される。単純なキーワードマッチではなく、「このタスクにはどのスキルが実際にうまく機能する傾向があるか？」という問いに答える。

Step 4: Execute & Observe（実行と観察）

スキル実行後、observe()が以下を記録する:

  • タスク内容
  • 選択されたスキル
  • 実行品質（成功度）
  • オプショナルシグナル（エラー、ツール障害など）

これらの実行痕跡はまずRedisバックのセッションメモリ（短期記憶）に格納される。

Step 5: Promote（昇格）

promote()は重要な実行痕跡を短期メモリから長期グラフストレージに移行し、タスクパターンとスキル間のpreference weight（選好重み）を更新する。

"Both successes and failures matter. Success teaches the router what to trust more. Failure teaches it what to avoid next time."
（成功も失敗も重要。成功はルーターに何をより信頼すべきかを教え、失敗は次に何を避けるべきかを教える）

つまり、短期的な実行痕跡が長期的なルーティング記憶に変換される。これがサイクルの核心であり、次回のルーティングが前回の学習を反映することで、スキルシステム全体が継続的に改善される。

知識グラフ内のスキル表現

cogneeの基本単位はDataPoint -- コンテンツとメタデータを運ぶPydanticモデルである。すべてのグラフノードに対応する埋め込みが存在し、意味的類似度と関係走査の間をシームレスに移動できる。

スキルは以下のグラフ構造で表現される:

// 概念的なグラフ構造
[Skill Node] --solves--> [TaskPattern Node]
[Skill Node] --has_trigger--> [Trigger Phrase]
[Skill Node] --complexity--> [Level]
[TaskPattern Node] --preferred_by--> [Skill Node] // weight: 0.0-1.0
[Execution Trace] --used--> [Skill Node]
[Execution Trace] --for_task--> [TaskPattern Node]
[Execution Trace] --result--> [success|failure|partial]

メタスキル

特に注目すべきは「メタスキル」の存在である。これはスキルルーティング自体をスキルとして定義したもので、エージェントにシステムの使い方を教える: ingest → route → load → execute → observe → promote。自己参照的な構造により、システムの使用方法自体が改善対象となる。

6. 実装詳細とコード例

基本的な使用法（6行）

import cognee, asyncio

async def main():
    await cognee.add("Cognee turns documents into AI memory.")
    await cognee.cognify()
    results = await cognee.search("What does Cognee do?")
    for result in results:
        print(result)

asyncio.run(main())

# pip または uv で
uv pip install cognee

# 環境変数設定
export LLM_API_KEY="your-openai-key"

7. 学術的背景: 自己改善エージェント研究

自己改善エージェントの6つのパラダイム

Yohei Nakajima（BabyAGI開発者）の整理による分類:

手法メカニズム代表例重み更新
リフレクションループ出力を自己批評して改善Reflexionなし
自己修正訓練誤り-修正ペアで学習STaR, SELFあり
自己生成カリキュラム独自タスクを作成・学習Self-Playあり
自己適応モデル編集を生成し自己更新SICAあり
コードレベル修正ポリシーを編集可能なコードとして扱うVoyagerなし

Cogneeのアプローチは主に「コードレベル修正」と「リフレクションループ」の中間に位置する。重みの更新はモデル自体ではなくグラフのエッジ重みに対して行われ、推論時のルーティングが変化する。

SAGE: スキルライブラリによる強化学習（2025年12月）

Jiongxiao Wang et al. による論文 (arXiv:2512.17102) は、cogneeとは独立に、スキルライブラリを強化学習に統合するフレームワークを提案した。

  • Sequential Rollout: 連鎖的なタスクを通じてスキルを蓄積
  • Skill-integrated Reward: 結果ベース報酬にスキル活用報酬を追加
  • AppWorldベンチマークでシナリオ目標達成率+8.9%、インタラクションステップ-26%、トークン-59%

ARIA: テスト時学習（NeurIPS 2025）

TikTok Payで1.5億MAUに展開されたAdaptive Reflective Interactive Agent。構造化された自己対話を通じて不確実性を評価し、知識ギャップを能動的に特定する。

メタ認知学習（OpenReview 2025）

"Effective self-improvement requires intrinsic metacognitive learning -- an agent's intrinsic ability to actively evaluate, reflect on, and adapt its own learning processes."

真の自己改善には、外部フィードバックだけでなく、学習プロセス自体を評価・反省・適応する内在的なメタ認知能力が必要とされる。

8. 実務への適用方法

段階的導入ロードマップ

Phase 1: 基礎メモリ（1-2日）

  • pip install cognee でインストール
  • 既存のドキュメントやコードベースをadd()で取り込み
  • cognify()で知識グラフを構築
  • search()でRAGの代替として検証

Phase 2: スキル構造化（3-5日）

  • 既存のSKILL.mdファイルをcogneeに取り込み
  • タスクパターンの自動生成を確認
  • ルーティングの精度を評価

Phase 3: フィードバックループ（1-2週間）

  • observe()による実行結果の記録を開始
  • promote()による長期学習の有効化
  • preference weightの変化をモニタリング

Phase 4: 本番運用

  • マルチテナント対応（ユーザー/グループごとのグラフ分離）
  • OTEL Collectorによるオブザーバビリティ
  • 評価フレームワークによる継続的な品質検証

9. 批判的分析: 限界と課題

課題領域具体的な問題深刻度
LLM依存 cognify段階でのエンリッチメントがLLMの品質に完全依存。タスクパターン抽出やトリガーフレーズ生成の精度はLLMの能力に制約される。誤ったパターン抽出は後続のルーティングに悪影響を及ぼす。 高
コールドスタート問題 preference weightが蓄積されるまでの初期フェーズではルーティングの精度が低い。十分な実行痕跡がなければ、意味検索のみに依存することになり、通常のRAGと大差ない。 中
フィードバックの質 observe()の品質スコアはどう生成されるのか。自動評価の場合、LLMによる自己評価のバイアスが問題になる。人間のフィードバックは正確だがスケールしない。 中
負の学習 初期の誤ったフィードバックがpreference weightを汚染すると、修正が困難。コンテキスト汚染と類似の問題がグラフレベルで発生しうる。 高
スケーラビリティ 100以上のスキルがグラフに存在する場合のルーティング性能は未検証。v0.3で1GBの処理に40分（100+コンテナ使用）。 中
理論的基盤 メタ認知学習の観点から、cogneeの現在のループは「外部フィードバックに基づく適応」であり、「内在的メタ認知」には達していない。学習プロセス自体の自己評価・自己改善はまだ実現されていない。 低〜中
実証データ不足 HotPotQAベンチマークでMem0/Graphiti/LightRAGを上回るとされるが、スキル自己改善ループの効果を定量的に示した公開ベンチマークは見当たらない。 中

cogneeの位置づけ: 何であり、何でないか

cogneeが提供するもの

  • スキルを知識グラフとして構造化する仕組み
  • 実行痕跡に基づくルーティングの最適化
  • 短期→長期の記憶移行メカニズム
  • 多様なバックエンドへの柔軟な接続
  • フレームワーク非依存のメモリ基盤

cogneeが提供しないもの

  • スキルの指示文自体の自動書き換え
  • モデル重みの更新（ファインチューニング）
  • 完全に自律的な新スキルの発見・創造
  • メタ認知的な学習プロセスの自己改善
  • 人間の判断を完全に代替するフィードバック

10. まとめ

調査結果の要約

Vasilije Markovic (@tricalt) が開発するcogneeは、AIエージェントのメモリ問題を解決するオープンソースの知識エンジンである。14.5k GitHub Starsを獲得し、Apache-2.0ライセンスで公開されている。

cogneeの自己改善スキル機能は、静的なSKILL.mdファイルを知識グラフに変換し、Ingest → Route → Execute → Observe → Promoteのフィードバックループを通じてスキルルーティングを継続的に最適化するアプローチである。核心的な技術は以下の3点に集約される:

  1. グラフ-ベクトルハイブリッド: タスクパターンとスキルの関係をグラフノードとエッジで表現し、かつベクトル埋め込みで意味検索を可能にする
  2. observe/promoteメカニズム: 短期的な実行痕跡（Redis）を長期的なルーティング記憶（グラフのpreference weight）に昇格させる
  3. メタスキル: システムの使用方法自体をスキルとして定義し、自己参照的な改善を可能にする

しかし、LLM依存、コールドスタート問題、フィードバック品質、負の学習汚染など、実用上の課題も明確に存在する。特に、現段階では「スキルのルーティングの改善」であって「スキルの指示文自体の自動改善」ではないという点は、期待と実装のギャップとして認識すべきである。

学術的には、SAGE（強化学習によるスキルライブラリ統合）、ARIA（テスト時学習）、メタ認知学習など、関連研究が急速に発展しており、cogneeの方向性は研究コミュニティの問題意識と合致している。
